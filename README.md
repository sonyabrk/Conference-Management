# Система управления конференциями

## Назначение
Приложение для организации научных и технических конференций:
учёт конференций и секций, регистрация докладов авторов, распределение
докладов по секциям и тайм-слотам, отслеживание статуса заявок.

## Целевая аудитория
Организаторы конференций, ответственные за формирование программы
мероприятия и координацию докладов.

## Предметная область
Проведение конференции предполагает деление на тематические секции,
в рамках которых авторы представляют доклады в отведённое время.
Система позволяет фиксировать конференции и секции, принимать заявки
на доклады, проверять занятость слотов и вместимость секций.

Правила предметной области:
- секция принадлежит конференции и вмещает ограниченное число докладов;
- заявка на доклад относится к секции и занимает тайм-слот;
- в одной секции нельзя создать две активные заявки на один и тот же слот;
- нельзя подать заявку в секцию, в которой не осталось свободных мест;
- отменённая заявка не удаляется, но перестаёт блокировать слот
  и не занимает место в секции.

## Основные сущности
- конференция (класс `Conference`);
- секция (класс `Section`);
- доклад / заявка на доклад (класс `Talk`);
- автор — атрибут заявки `Talk.author`.

## Возможности (актуально после ПР3)
- просмотр и поиск секций и конференций;
- проверка вместимости секции;
- сортировка секций по вместимости;
- отбор секций по количеству свободных мест;
- проверка доступности тайм-слота для доклада;
- добавление конференций и секций;
- добавление заявки на доклад;
- отмена заявки на доклад (заявка остаётся в списке со статусом «отменена»);
- сохранение данных между запусками программы.

## Классы

### Conference — конференция
Основные атрибуты:
- `id` — идентификатор конференции;
- `name` — название.

Основные методы:
- `matches()` — проверка, содержит ли название заданную подстроку;
- `to_dict()` — преобразование в словарь для JSON;
- `from_data()` (`@classmethod`) — создание объекта из словаря;
- `__str__()` — строковое представление.

### Section — секция
Основные атрибуты:
- `id` — идентификатор секции;
- `name` — название;
- `conference` — объект `Conference`, которому принадлежит секция;
- `capacity` — вместимость (максимальное число докладов).

Основные методы:
- `free_slots()` — сколько докладов ещё помещается в секцию
  (отменённые заявки не учитываются);
- `has_free_slots()` — проверка, что свободно не меньше заданного числа мест;
- `matches()` — проверка названия по подстроке;
- `validate_capacity()` (`@staticmethod`) — проверка корректности вместимости;
- `to_dict()` — преобразование в словарь для JSON (вместо объекта
  конференции сохраняется `conference_id`);
- `from_data()` (`@classmethod`) — создание объекта из словаря
  и найденного объекта `Conference`;
- `__str__()` — строковое представление.

### Talk — заявка на доклад
Основные атрибуты:
- `id` — идентификатор заявки;
- `section` — объект `Section`, в которую подана заявка;
- `author` — автор доклада;
- `title` — название доклада;
- `time_slot` — тайм-слот;
- `is_cancelled` — признак отмены заявки.

Основные методы:
- `cancel()` — отмена заявки (меняет состояние объекта);
- `blocks_slot()` — проверка, блокирует ли заявка указанный тайм-слот
  в секции (активна, та же секция, то же время);
- `to_dict()` — преобразование в словарь для JSON (вместо объекта
  секции сохраняется `section_id`);
- `from_data()` (`@classmethod`) — создание объекта из словаря
  и найденного объекта `Section`;
- `__str__()` — строковое представление с учётом состояния заявки.

## Взаимодействие объектов
```text
Talk ──относится к──> Section ──входит в──> Conference
```
Заявка `Talk` хранит ссылку на объект `Section`, а секция `Section` —
на объект `Conference`. Благодаря этому данные связанных объектов доступны
напрямую, например `talk.section.name` или `talk.section.conference.name`.

Логика, относящаяся к одному объекту, находится в его методах:
вместимость секции считается в `Section.free_slots()`, занятость слота
определяется в `Talk.blocks_slot()`. Функции модулей работают с коллекциями
объектов (`list[Conference]`, `list[Section]`, `list[Talk]`) и используют
методы объектов, не дублируя их логику.

При отмене заявки вызывается `talk.cancel()`: объект остаётся в коллекции,
но перестаёт блокировать слот и занимать место в секции.

## Хранение данных
Данные хранятся в JSON-файлах:
- `data/conferences.json`;
- `data/sections.json`;
- `data/talks.json`.

При загрузке данные из JSON преобразуются в объекты `Conference`,
`Section` и `Talk`, при этом восстанавливаются связи между ними.
При сохранении объекты преобразуются обратно в словари. Связанные объекты
в JSON представлены идентификаторами: `conference_id` в секции
и `section_id` в заявке.

Если связанный объект не найден (например, у секции указана несуществующая
конференция), такая запись пропускается с сообщением в консоль.
При отсутствии или повреждении файла загружается пустой список.

Преобразование JSON и объектов выполняется только в `storage.py`.

## Назначение модулей
- `main.py` — точка запуска, меню приложения и пользовательские сценарии;
- `models/__init__.py` — экспорт классов `Conference`, `Section`, `Talk`;
- `models/conferences.py` — класс `Conference` и функции работы
  с конференциями;
- `models/sections.py` — класс `Section` и функции работы с секциями:
  поиск, проверка вместимости, отбор по свободным местам (генератор),
  сортировка;
- `models/talks.py` — класс `Talk` и функции работы с заявками:
  проверка слота, создание и отмена заявки;
- `storage.py` — сохранение и загрузка данных (JSON <-> объекты);
- `utils.py` — вспомогательные функции безопасного ввода
  (`input_int()`, `input_date()`);
- `data/` — JSON-файлы данных;
- `tests/` — автоматизированные тесты.

## Требования
- Python 3.9 и выше;
- pytest;
- flake8.

Установка зависимостей:
pip install -r requirements.txt

## Запуск программы
python main.py

После запуска отображается главное меню. Данные сохраняются
после изменяющих операций и при выходе из программы.

## Запуск тестов
python -m pytest -v

Тесты проверяют:
- создание объектов `Conference`, `Section`, `Talk` и значения их атрибутов;
- строковое представление объектов;
- методы классов (`free_slots()`, `cancel()`, `blocks_slot()`,
  `from_data()`, `to_dict()`);
- операции с коллекциями: добавление, поиск, фильтрацию, сортировку;
- правило доступности слота, в том числе что отменённая заявка
  слот не блокирует;
- контроль вместимости секции;
- связи между объектами и корректность загрузки и сохранения JSON.
